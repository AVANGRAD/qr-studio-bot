# Decisions

- Render Free + webhook, не polling: дешевле и стабильнее для Telegram.
- Self-ping 600 с, чтобы укладываться в 750 free-часов и не конкурировать с чужими сервисами.
- Не использовать чужие Render-воркспейсы/ключи.
- Шрифт Roboto (OFL) вместо системного DejaVu: кириллица и переносимость.
- Для рискованных глаз и модулей — безопасная база + лёгкий overlay.
- SVG: силуэт/логотип как встроенный PNG, QR-модули векторные — точное совпадение с PNG.
- Лимит контента 1200 символов: баланс плотности QR и читаемости.
- Mini App отдаётся тем же aiohttp-сервером по `/app`; выбор приходит в бота через `POST /app/apply` с подписанным `initData` и валидируется handler-ом. `WebApp.sendData` оставлен только fallback для keyboard-кнопок.
- Плитки Mini App — статические PNG в `webapp/thumbs/`, чтобы Render не тратил CPU на 105 превью при каждом открытии.
- Кнопка Mini App добавляется только в private-чатах: Telegram не поддерживает `web_app` в группах.
- `WEBHOOK_SECRET` не генерируется через Render `generateValue`; допустимый секрет — URL-safe/hex, иначе `Settings` хэширует его.
- Лист — pointed-oval с черешком; плашки уменьшены до 0.60/0.66, чтобы силуэт читался.
- Mini App доступен постоянной кнопкой меню, командой `/app` и inline-кнопкой в редакторе; это убирает зависимость от поиска кнопки в клавиатуре.
- Настройки Mini App без активного draft сохраняются в FSM и применяются после ввода текста.

- Figure-режим включён по умолчанию для не-square форм: QR должен выглядеть частью силуэта, а не квадратной вставкой. `RenderOptions.silhouette` остаётся opt-in для библиотеки, чтобы не ломать API.
- Если центральный безопасный квадрат задевает вырезы или края силуэта, используется frame-плашка. Это приоритетнее визуальной агрессии: непроверяемый QR недопустим.
- Плитки и preview в Mini App обновляются через cache-bust/`no-store`, чтобы после деплоя не показывались старые квадратные превью.

- Фото-режим: полное фото вписывается в квадрат, а свободные поля заполняются размытой затемнённой cover-копией. Так пользователь видит всё фото, а не только центральный кроп.
- QR в фото-режиме размещается на светлой карточке 42% в правом нижнем углу, с почти непрозрачным фоном (alpha 244). Это сохраняет контраст QR и оставляет фото видимым вокруг карточки.
- Фото-режим имеет приоритет над shape/silhouette/frame: форма не применяется, чтобы не ломать композицию и сканируемость.
- Фото принимается до создания draft (`pending_photo`) и после; хранится как JPEG до 1600 px, чтобы не раздувать FSM MemoryStorage.
- Фото-режим не добавлен в статический каталог Mini App: загрузка файла выполняется в Telegram-боте.

- Встроенные логотипы — только нейтральные иконки, сгенерированные из силуэтов; брендовые логотипы не добавляются из-за товарных знаков. Свой файл пользователь загружает отдельно.
- «Медальон» — круглая подложка с пропорцией 1.4; режим хранится как `badge`, подпись — «медальон».
- `flower` использует безопасную базу `dot` + overlay: одиночная фигура с внутренним вырезом давала scan-провал на 512 px.
- `capsule`, `octagon` и `spark` проверены как самостоятельные безопасные формы глаз; `heart` оставлен на safe-base, потому что сердце в центре ломает finder-паттерн.
- Мини-каталог расширен до 134 плиток; cache-bust поднят до `?v=variety1`.

- `sendData` не используется как основной путь: menu/inline Mini App его не поддерживают. Серверный Apply проверяет HMAC `WebAppData` и `auth_date` (6 часов), затем передаёт synthetic `web_app_data` в тот же dispatcher.
- `app.js` подключается с cache-bust (`?v=apply1`), иначе Telegram WebView может держать старый JS после деплоя.

- Полная локализация `ru/en` выбрана пользователем; язык выбирается при первом `/start`, а не только автоматически по Telegram.
- Fallback `resolve_lang()`: без кода — `ru`; `en*` — `en`; `ru/uk/be/kk` — `ru`; неизвестный непустой — `en`. Это компромисс между русскоязычной аудиторией и международным default.
- Язык хранится в FSM как `lang`, чтобы выбор пользователя переживал смену сценария; `clear_flow()` сохраняет его. Ограничение `MemoryStorage` принято осознанно: после рестарта picker появится снова.
- `LanguageMiddleware` стоит на `dp.update.outer_middleware` после FSM: это единственный способ применить язык ко всем дочерним routers, включая synthetic update из Mini App.
- Mini App выбирает язык URL → `localStorage` → Telegram → browser: URL (per-chat menu/`/app`) важнее локального выбора, а сохранённый выбор переживает перезапуск WebView.
- Telegram-команды: default English + `ru` scope; picker не меняет scope уже открытого чата, это отмечено как ограничение.
- В Mini App добавлен внутренний RU/EN toggle: он меняет UI сразу, а Apply отправляет `lang` в бота. Это позволяет менять язык без перезапуска и не спамить чат отдельным сообщением при каждом переключении.
- Per-chat `MenuButtonWebApp` с `?lang=` обновляется после `/start`, `/language` и Apply; global menu button остаётся fallback, если Telegram API недоступен.
- `Draft.logo_emblem` добавлен, чтобы английская подпись не зависела от русской `logo_label`; старые draft остаются совместимыми.
- `RenderResult.warning_codes` добавлен, чтобы рендер не зависел от языка, а caption локализовал предупреждения.
- Для аналитики выбран PostgreSQL/Supabase, а не GitHub: коммит на каждого пользователя создаёт гонки, лишние деплои, API-лимиты и риск утечки ID в публичном репозитории.
- `analytics` — отдельная схема в той же БД: `users` для состояния и `events` для истории; текст сообщений/QR не сохраняется.
- Запись активности выполняется в `dp.update.outer_middleware`, чтобы покрывать messages, callbacks и synthetic Mini App updates; ошибки БД не ломают обработку update.
- «Ушёл» определяется как отсутствие активности 30+ дней (`dormant`); `blocked_at` выставляется только при фактическом 403 от Telegram. Точного leave-события Bot API не даёт.
- `/stats` закрыт `ADMIN_ID`; без него команда молчит, чтобы не раскрывать статистику пользователям.
- `DATABASE_URL` опционален: без него аналитика отключается, бот сохраняет прежнее поведение.
- Для поддержки выбран отдельный Telegram-бот на отдельном токене, но один Render-сервис и один процесс: так запуск одного сервиса поднимает оба бота без второго деплоя.
- Webhook поддержки имеет отдельный secret/path, чтобы не конфликтовать с основным ботом; support-token не переиспользуется как основной.
- Тикеты mapping хранятся в `support.tickets` в PostgreSQL, потому что reply-связь должна переживать рестарт Render; без БД используется память.
- Администратор обязан сам нажать `/start` в support-боте: Bot API не позволяет боту инициировать чат.

## Безопасность (2026-11-19)

- Webhook path — не секрет: путь вычисляется как SHA256-хеш от отдельного header-секрета. Это позволяет ротировать секрет без публикации пути и не логировать URL целиком.
- Для приложения выбрана отдельная роль `qr_app` без `CREATEDB`/`CREATEROLE`; миграции — отдельный административный процесс. Приложение не должно иметь DDL-права.
- Supabase CA (`prod-ca-2021.crt`) закоммичен как публичный сертификат; TLS использует `verify-full`-поведение, а не `ssl="require"`.
- Rate limits in-memory: достаточно для одного Render-инстанса; при масштабировании/нескольких инстансах нужно вынести в общий store.
- `WEBHOOK_SECRET`/`SUPPORT_WEBHOOK_SECRET` считаются постоянными секретами, но ротируются при компрометации; Telegram bot token не имеет срока и требует 2FA/защиты.
- GitHub PAT/Render API key лучше выпускать на срок 1 год (или короче) с минимальными scopes; бессрочные токены не рекомендуются.
